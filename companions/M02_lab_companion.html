Module 2 Learning Goals

By the end of this lab you should be able to:

  • describe a text dataset so another analyst can check it;
  • find missing and repeated text;
  • apply a written label policy with a quoted evidence phrase;
  • explain why some records are kept apart for a fair test later.

The main idea: checking the data and defining a correct label are part of the analysis. They come before any method. One row in Part 1 is one feedback message, not one customer.

Part 1B: Label 12 Messages (Steps 1.7–1.10)

1.7 Read the policy and make the worksheet

Policy version 1 (v1) has three labels:

  • review: an open problem or a clear request for help. A question that asks how to do something counts as a request for help.
  • no_review: the problem is clearly solved, or the customer gives an opinion and needs no help.
  • unclear: too little context to decide. Staff would ask the customer for more details.

A label says whether staff should look at a message. It does not approve a refund or any other action. A star rating alone does not decide the label.

2.7 Look for near-repeats

Each complaint's opening uses the same rule as the split: lower case, every run of non-letters turned into one space, then the first 100 characters.

# Build the opening of each narrative in four small steps.
lowered = complaints["narrative"].str.lower()
# Replace every run of non-letters with one space.
letters_only = lowered.str.replace(r"[^a-z]+", " ", regex=True)
# Remove the spaces at both ends, then keep the first 100 characters.
complaints["opening"] = letters_only.str.strip().str[:100]

# True for every complaint whose opening also appears in another complaint.

2.8 Check that the split keeps similar letters together

If a letter is in train and a near-copy is in test, a model can score well by remembering the template. The test then looks better than the model's work on new complaints. This is leakage, the same risk as FB005/FB020. The course split gives complaints with the same product and the same opening the same split. This is one grouping rule: it flags possible template matches, but it can miss related complaints and group unrelated ones. You check that the split follows it.

# For each product-and-opening group, count how many different splits it uses.
shared_complaints = complaints.loc[shared]
splits_per_group = shared_complaints.groupby(["product", "opening"])["split"].nunique()

# How many groups use 1 split, 2 splits, and so on.
splits_per_group.value_counts()

Result

All 79 product-and-opening groups use 1 split. No group within a product crosses splits.
